## UI Implementation Requirements

### SCHEDULED Status Time Display

**Requirements:**
1. Show countdown timer when status === "SCHEDULED" and mpStatus?.waitingTime is defined
2. Time formatting rules:
   - Less than 60 seconds: `(45s)`
   - Less than 3600 seconds: `(5m 30s)`
   - Less than 86400 seconds: `(2h 15m)`
   - More than 1 day: `(1d 6h)`

**Implementation Example:**
```javascript
if (status === "SCHEDULED" && mpStatus?.waitingTime !== undefined) {
  const waitingTime = mpStatus.waitingTime;
  if (waitingTime < 60) {
    text += ` (${waitingTime}s)`;
  } else if (waitingTime < 3600) {
    text += ` (${Math.floor(waitingTime / 60)}m ${waitingTime % 60}s)`;
  } else if (waitingTime < 86400) {
    const hours = Math.floor(waitingTime / 3600);
    const minutes = Math.floor((waitingTime % 3600) / 60);
    text += ` (${hours}h ${minutes}m)`;
  } else {
    const days = Math.floor(waitingTime / 86400);
    const hours = Math.floor((waitingTime % 86400) / 3600);
    text += ` (${days}d ${hours}h)`;
  }
}
```

**Required Properties:**
- status: Must be "SCHEDULED"
- waitingTime: Number in seconds until task execution

## Marketplace Execution Order Analysis

### ✅ IMPLEMENTED: Sequential Execution with MagicEden Last

### New Architecture (COMPLETED)
- **Phase 1**: OpenSea and Blur jobs execute concurrently
- **Phase 2**: MagicEden job executes only after OpenSea AND Blur complete
- **Event-Driven**: BullMQ completion events trigger sequential execution
- **Fallback Protected**: 5-minute timeout ensures MagicEden runs even if prerequisites fail

### Implementation Details

#### Job Creation Logic (Modified)
```typescript
// Phase 1: Schedule OpenSea and Blur jobs immediately
const openseaJobs = jobs.filter(job => job.name === OPENSEA_SCHEDULE);
const blurJobs = jobs.filter(job => job.name === BLUR_SCHEDULE);
const magicedenJobs = jobs.filter(job => job.name === MAGICEDEN_SCHEDULE);

// OpenSea and Blur start immediately
if (openseaJobs.length > 0) await queue.addBulk(openseaJobs);
if (blurJobs.length > 0) await blurQueue.addBulk(blurJobs);

// MagicEden scheduled sequentially
if (magicedenJobs.length > 0) {
  scheduleSequentialMagicedenJob(taskId, magicedenJobs[0]);
}
```

#### Completion Tracking System
- **`marketplaceCompletionTracker`**: Tracks completion state per task
- **Event Handlers**: Listen to schedule job completion events
- **Auto-Trigger**: MagicEden job created when both prerequisites complete

#### Safety Features
1. **Timeout Fallback**: MagicEden runs after 5 minutes regardless
2. **Single Marketplace Mode**: Preserves behavior when only MagicEden selected
3. **Error Recovery**: MagicEden still runs if prerequisites fail
4. **Cleanup**: Completion tracking cleaned up with task resources

### Marketplace Functions (Unchanged)
1. `processOpenseaScheduledBid` → OPENSEA_SCHEDULE job
2. `processMagicedenScheduledBid` → MAGICEDEN_SCHEDULE job  
3. `processBlurScheduledBids` → BLUR_SCHEDULE job

### Execution Flow
1. **Task Start**: `initializeMarketplaceCompletion()` sets up tracking
2. **Phase 1**: OpenSea + Blur jobs created via `queue.addBulk()`
3. **Completion Events**: Workers trigger `markMarketplaceComplete()`
4. **Phase 2**: MagicEden job auto-created when both prerequisites complete
5. **Cleanup**: `cleanupMarketplaceCompletion()` removes tracking

### Expected Behavior
- **Multi-marketplace tasks**: MagicEden waits for OpenSea/Blur completion
- **Single marketplace**: MagicEden-only tasks execute immediately
- **Mixed scenarios**: Only enabled marketplaces affect prerequisites
- **Failure handling**: Timeout ensures MagicEden always runs eventually
